# План и результаты тестирования

## Стратегия

Тесты разделены на три уровня. `test_security.py` проверяет криптографические примитивы. `test_service.py` тестирует бизнес-правила с реальной временной SQLite. `test_api.py` запускает HTTP-сервер на случайном порту и проходит API как внешний клиент.

## Набор сценариев

| ID | Сценарий | Уровень | Ожидаемый резуль |
|---|---|---|---|
| T-01 | Одинаковые пароли | Unit | Разные хеши из-за соли; оба верифицируются |
| T-02 | Нарушение политики пароля | Unit | Перечень недостающих групп символов |
| T-03 | Email normalization | Unit | Пробелы удалены, регистр приведён |
| T-04 | Session round trip | Unit | HMAC-токен и CSRF приняты |
| T-05 | Tampered/expired session | Unit | Токен отклонён |
| T-06 | Регистрация и вход | Service | Аккаунт найден без учёта регистра email; неверный пароль отклонён |
| T-07 | Дубль email | Service | ValidationError |
| T-08 | CRUD задачи | Service | Create, update, stats, delete согласованы |
| T-09 | Изоляция аккаунтов | Service | Второй аккаунт не видит, не меняет и не удаляет чужую задачу |
| T-10 | Stale update | Service | Optimistic locking отклоняет старую version |
| T-11 | Поиск, фильтр и валидация | Service | Выборка точна; пустое имя и неверная дата отклонены |
| T-12 | Health/session | HTTP | 200, `database=ok`, анонимная сессия |
| T-13 | Ошибка входа | HTTP | 401 без раскрытия причины |
| T-14 | Защищённый route | HTTP | 401 без session cookie |
| T-15 | CSRF | HTTP | 403 без заголовка на POST |
| T-16 | CRUD через API | HTTP | 201/200, поиск находит задачу, DELETE успешен |
| T-17 | Регистрация через API | HTTP | 201, cookie и CSRF возвращены |

## Запуск

```bash
python3 -m unittest discover -v
```

## Результат

На 17 сентября 2026 года все 17 автотестов проходят. Дополнительно выполняется `compileall`, `PRAGMA integrity_check` и ручной браузерный сценарий: вход в демо, создание карточки, редактирование, перемещение, поиск и удаление.
